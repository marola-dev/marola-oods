# Cloudflare R2: the bucket, its tokens and cost

The safety rules and the least-privilege token rules are adapted from
backblaze-labs/claude-skill-b2-cloud-storage `b2-cloud-storage` and backblaze-labs/b2-mcp's
`b2-least-privilege-keys` (MIT), re-pointed from B2 to R2; see [NOTICE.md](../NOTICE.md). R2
facts are from Cloudflare's R2 docs (<https://developers.cloudflare.com/r2/>), not yet checked
against a live bucket.

| | |
|---|---|
| Bucket | `br-open-ocean-data-storage`, private (no `r2.dev` URL, no custom domain), location Automatic, Standard class |
| Endpoint | `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`, region `auto`; SigV4 only; path style |
| Layout | `catalog/oods.ducklake` (one key, rewritten by every commit), `catalog/backup/` (named copies), `lake/**.parquet` (written once, deleted by cleanup), `exports/` |

`<ACCOUNT_ID>` comes from `OODS_S3_ENDPOINT` (the workflows build it from the variable
`CLOUDFLARE_R2_ACCOUNT_ID`). The account ID is not secret, but it is never needed in a file.

## Rules for this bucket (on top of SKILL.md's Safety)

1. Default to read-only: `list-objects-v2`, `head-object`, `get-object` to a temp file. Nothing
   else without a person.
2. Never call the Cloudflare API to list, create or roll tokens; never run `wrangler login` or
   read `~/.wrangler/` or `~/.aws/credentials`.
3. A delete, a lifecycle rule, a bucket setting (public access, CORS, a custom domain): the dry run
   or the exact rule first, shown to the person, then their typed "yes". Anything else aborts.
4. Never make the bucket public. Never write a token, access key or secret to a file.
5. Bounded listings: page through, print at most 50 sample rows, summarise by prefix.

## No versions: an overwrite is final

R2 has no object versioning: `ListObjectVersions` is not supported, and an upload of
`catalog/oods.ducklake` replaces the only copy. A deleted Parquet file is gone. So the backups are
the named copies under `catalog/backup/` ([recovery.md](recovery.md) §3). Cleanup deletes a file
only 30 days after the last snapshot that used it expired ([maintenance.md](maintenance.md)), so a
backup up to 30 days old still finds its newest snapshot's files.

AWS CLI v2's newer default checksums are not all accepted by every S3-compatible store; keep
`AWS_REQUEST_CHECKSUM_CALCULATION=when_required` and `AWS_RESPONSE_CHECKSUM_VALIDATION=when_required`
on every call.

## Lifecycle: expire old backups

R2's object lifecycle rules delete objects by prefix and age, and abort unfinished multipart
uploads. Recommend one rule, set by a person (R2 → the bucket → Settings → Object lifecycle rules):

| Rule | Prefix | Action |
|---|---|---|
| `expire-catalog-backups` | `catalog/backup/` | delete objects 30 days after upload |
| `abort-multipart` | (all) | abort incomplete multipart uploads after 1 day |

Never a rule on `catalog/oods.ducklake` or `lake/`: DuckLake's own maintenance decides when a
data file goes. An agent proposes the exact rule and reads it back afterwards
(`aws s3api get-bucket-lifecycle-configuration`).

## The two tokens

R2 has no service accounts. Each workload gets an **Account API token** (R2 → Manage R2 API
Tokens → Create Account API token), owned by the account rather than a person, scoped to this
bucket only.

| Token | Who | Permission | Where |
|---|---|---|---|
| `marola-oods-etl` | `oods-lake` jobs, a person's maintenance run | Object Read & Write, this bucket | marola-oods: `CLOUDFLARE_R2_ACCESS_KEY_ID`, `CLOUDFLARE_R2_SECRET_ACCESS_KEY` (secrets), `CLOUDFLARE_R2_ACCOUNT_ID`, `CLOUDFLARE_R2_TOKEN_NAME` (variables); the workflow maps them to `OODS_S3_KEY_ID`/`OODS_S3_SECRET`/`OODS_S3_ENDPOINT`/`OODS_KEY_NAME` |
| `marola-site-read` | marola-site, marola-ml, inspection | Object Read only, this bucket | not created yet (MIP-0075 §5.6, a person's step): `CLOUDFLARE_R2_READ_ACCESS_KEY_ID`, `CLOUDFLARE_R2_READ_SECRET_ACCESS_KEY` |

Least privilege: never an Admin permission (it can create and delete buckets), never "Apply to
all buckets", one token per workload. Cloudflare shows the secret once, at creation. A token that
appears in the chat or a log: tell the person to roll it (R2 → Manage R2 API Tokens), and do not
repeat it.

## How big is it

R2 bills only current objects, so the listing is the bill:

```bash
AWS_ACCESS_KEY_ID="$OODS_S3_KEY_ID" AWS_SECRET_ACCESS_KEY="$OODS_S3_SECRET" AWS_DEFAULT_REGION=auto \
  aws --endpoint-url "https://$OODS_S3_ENDPOINT" s3api list-objects-v2 \
  --bucket br-open-ocean-data-storage --output json \
  --query '{objects: length(Contents || `[]`), bytes: sum(Contents[].Size || `[0]`)}'
aws ... s3api list-multipart-uploads --bucket br-open-ocean-data-storage   # unfinished uploads count too
```

The bucket's Metrics tab in the dashboard shows storage and Class A/B operations per month.

The live Parquet alone, from DuckDB (metadata only, never `content`):

```sql
-- needs: r2
SELECT count(*) AS files, sum(size) AS bytes FROM read_blob('s3://br-open-ocean-data-storage/lake/**');
```

The same on the local lake:

```sql
SELECT count(*) AS files, sum(size) AS bytes FROM read_blob('.tmp/lake/data/**');
```

## Price and the free tier

From R2's pricing page (<https://developers.cloudflare.com/r2/pricing/>):

- Storage: 10 GB-month free (Standard class); then $0.015 per GB-month.
- Class A operations (writes, lists): 1 million a month free; then $4.50 per million.
- Class B operations (reads): 10 million a month free; then $0.36 per million.
- Egress: free. Infrequent Access storage has no free tier and a retrieval fee: never use it here.

Spec 001 aims the whole bucket under 100 MB with 30 days of snapshots (SC-005), 1% of the free
tier; the backups add one catalog copy (a few MB) per day kept.

Enabling R2 needs a payment method on the account, and use above the free tier is billed to it:
Cloudflare has no spend cap. A usage notification (Notifications → Add → billing usage) is a
person's step.
